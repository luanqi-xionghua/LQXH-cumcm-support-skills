# CUMCM Paper Review — 分章自查编排

本技能是**编排器**:自己不发明检查标准,每章的判定规则一律来自被调度的检查技能原文。定位为纯诊断工作流:

- 不修改用户的论文、代码、数据;所有产出只写入 `review_out/`;
- 不评分、不排位(打分排位不在本流程内,本包也未收录评分类技能);
- 默认静态检查;运行用户代码只可能发生在第 07 项,且必须用户对当次运行单独授权。

产出物:`review_out/` 下 1 份任务基准、7 份分章检查片段、1 份总报告 `cumcm-paper-review-report.md`。

## 0. 前置检查

1. 确定技能根目录:技能目录因 agent 软件而异(常见用户级:ZCode `~/.zcode/skills`、Claude Code `~/.claude/skills`、Codex CLI `~/.codex/skills`;项目级 `<工作区>/.<软件>/skills` 同理)。逐一探测,取存在分章检查技能的那个;都找不到时询问用户技能安装位置,或确认改走"按路径直读"模式(下一节)。
2. 逐一确认下表技能的 `SKILL.md` 存在,并记录每个技能的实际绝对路径(后续子代理提示词必须携带):

| 序号 | 技能 | 片段文件 | 主要输入 |
|---|---|---|---|
| 01 | abstract-checker | 01_abstract.md | 摘要 |
| 02 | problem-restatement | 02_restatement.md | 赛题 + 问题重述章 |
| 03 | problem-analysis-checker | 03_problem_analysis.md | 赛题 + 问题分析章 |
| 04 | model-assumption-checker | 04_assumptions.md | 赛题 + 模型假设章 |
| 05 | symbol-notation-checker | 05_symbols.md | 完整论文(或仅符号表) |
| 06 | model-solution-checker | 06_model_solution.md | 赛题 + 建模求解各章 |
| 07 | reference-appendix-checker | 07_reference_appendix.md | 论文 + 附录 + 支撑材料 |

3. 有缺失时:停止调度,列出缺失清单并给出安装指引(把对应技能文件夹整体复制进技能根目录,重启会话/重新加载技能)。仅当用户明确同意跳过时才继续其余项,总报告中对应章节标"未检查(技能缺失)"。

## 0.1 可移植性

本工作流只依赖三类能力:**读文件(必需)**、技能加载机制(可选)、子代理派生(可选)。因此不绑定特定 agent 软件——遵循 Agent Skills 规范的软件按技能方式安装;没有技能发现机制的软件,由用户给出包所在路径,所有技能一律按 SKILL.md 直读执行,工作流同样完整可用。缺可选能力时按下表降级,不得中断流程:

| 缺少的能力 | 降级方式 |
|---|---|
| 技能加载机制(Skill 工具/`$技能名`) | 一律 Read 技能 SKILL.md + references/ 后照其执行 |
| 子代理派生(Agent/Task 等) | 全部检查由主对话内联执行(见第 3 节),完成一项沉淀一项 |

## 1. 材料盘点(一次性,不得分技能反复追问)

向用户一次性收集并确认:

- **必需底线**:完整赛题(含附件说明)+ 论文全文或全部章节文本。二者有缺时,先按 references/workflow.md 第 1 节"材料边界矩阵"说明每项检查能做到的程度,由用户决定补料或带"无法核验"继续。
- **一次性问清**:竞赛名称(默认高教社杯国赛)、是否提供当届官方格式规范、是否提供代码/数据/运行结果、本次范围(默认全部 7 项,允许点名部分章节)。
- 材料若以对话内文本给出,先原样落盘到 `review_out/materials/`(如 problem.md、paper.md),此后一律以文件路径传递,保证子代理拿到完整材料,不得截断。
- 建立 `review_out/`(默认建在论文所在目录;无法确定时用当前工作目录)。

## 2. 任务基准(共享底稿)

从赛题重建任务基准:每一问的目标、输入、约束、指定输出,连同附件清单,写入 `review_out/00_baseline.md`。该底稿随子代理提示词分发;但各检查器自身要求的完整审题流程不得用它替代。

## 3. 调度检查

- **优先子代理隔离执行**:所在软件具备子代理能力时(名称随软件而异,如 Agent/Task/sub-agent),每个检查器派一个子代理,避免 7 份规则文件全部进入主对话。提示词按 references/workflow.md 第 2 节模板逐字段填写,必须自包含。
- **分两波并行**:第一波 01–04(赛题与论文前部即可开工);第一波全部返回后再派第二波 05–07(需要全文与支撑材料)。环境不支持并行或无子代理能力时,按序号 01→07 串行内联执行。
- **技能加载方式**:优先用所在环境的技能加载机制(如 Skill 工具、`$技能名` 调用)加载对应技能;若不可用,则直接 Read 该技能的 SKILL.md 与其 references/ 下全部规则文件并完整遵循。两种方式均视为调用该技能,判定标准必须出自技能原文。
- **降级**:所在软件无子代理能力,或同一检查器子代理两次失败时,由主对话按 references/workflow.md 第 3 节"内联执行"流程自查。
- 片段文件缺失或为空:重跑一次该检查器;再失败则在总报告标"未完成"并说明原因。

## 4. 汇总总报告

1. Read 全部片段;跨检查器去重——同一问题被多个检查器命中时合并为一条,保留全部证据位置;交叉一致性问题(正文↔符号表、正文↔附录、声明↔AI 材料等)单独归类。去重细则见 references/workflow.md 第 4 节。
2. 按 assets/report-template.md 生成 `review_out/cumcm-paper-review-report.md`,结构:元信息与材料范围 → 总览表(各章评级与 P0–P3 计数)→ Top 问题(P0/P1 全列)→ 分章诊断浓缩 → 交叉一致性问题 → 无法核验清单 → 修改优先级路线 → 片段索引。
3. 报告开头必须声明材料范围与检查边界;"未发现"不等于"不存在"。总报告只能浓缩引用片段结论,不得改写。

## 硬约束

- 只读诊断:所有产出只写入 `review_out/`;用户只要诊断时不得顺手改论文,除非另行明确要求。
- 严重度统一用 P0–P3(定义见 references/output-standard.md);片段格式见 assets/fragment-template.md。
- 不补造文献、数据、结果;无法核验的一律如实标注,不得判错。

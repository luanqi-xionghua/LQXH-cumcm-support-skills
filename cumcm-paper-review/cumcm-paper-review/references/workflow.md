# 工作流细则

## 1. 材料边界矩阵

材料盘点阶段据此向用户说明"能给到什么程度的检查";片段状态标"受限检查"时必须引用本表。

| 检查器 | 必需输入 | 可选增强 | 缺料时行为 |
|---|---|---|---|
| 01 abstract | 摘要文本 | 赛题、全文(仅作交叉核对,非必需) | 无赛题时不做事实一致性验证,并如实声明 |
| 02 restatement | 赛题 + 问题重述章 | 附件说明 | 缺赛题或重述章 → 该项无法开工,标无法核验 |
| 03 problem-analysis | 赛题 + 问题分析章 | 拟用模型、框架图、论文正文 | 缺正文 → 涉及后文对应关系标"无法核验",不判错 |
| 04 assumptions | 赛题 + 模型假设章 | 数据处理过程、检验、正文 | 同上 |
| 05 symbols | 完整论文 | —(仅有符号表时降级为局部审查) | 只有符号表 → 全文一致性标"无法核验" |
| 06 model-solution | 赛题 + 模型建立/求解/结果/检验/灵敏度全部内容 | 数据附件、源代码、运行环境 | 缺代码 → 数值复现、代码一致性标"无法核验",不判错 |
| 07 reference-appendix | 论文(含参考文献与附录) | 代码、数据、结果、当届规则、AI 详情材料 | 缺程序 → 只做静态检查并声明未验证;运行代码需用户对当次运行单独授权 |

## 2. 子代理提示词模板

逐字段替换 `{...}` 后整段发出;提示词必须自包含,不得依赖主对话上下文。

```text
你是数学建模论文分章检查的执行者,只负责第 {NN} 项检查,完成后即结束。

【调用技能】
优先用所在环境的技能加载机制(如 Skill 工具、$技能名 调用)加载 `{SKILL_NAME}`;
若不可用,Read `{SKILL_PATH}/SKILL.md`,并按其要求完整 Read 其 references/ 下全部规则文件后再开工。
判定标准一律以技能原文为准,不得用你自己的习惯替代。

【材料】(均为绝对路径;材料为内联文本时已由编排器落盘)
- 赛题:{PROBLEM_PATH}
- 论文/相关章节:{PAPER_PATH}
- 其他材料:{EXTRA_PATHS 或 "无"}
- 共享任务基准:Read {BASELINE_PATH}(仅供参考,不得替代技能自身的审题流程)
- 当届官方规则:{RULES_PATH 或 "未提供,按技能内置建议执行并注明"}

【输出】
把检查片段写入 {FRAG_PATH}(覆盖写),格式严格如下。严重度定义:
P0=致命(违规/硬伤) P1=严重(明显失分) P2=中等(影响印象) P3=轻微(润色级)。

# {NN} {检查名称}
- 状态:完整检查 | 受限检查(原因) | 未完成(原因)
- 依据材料:{实际使用的文件}
- 执行技能:{SKILL_NAME}

## 诊断结论
{3-5 句总体判断}

## 问题清单
| # | 严重度 | 位置 | 问题描述 | 证据 | 修改建议 |
|---|---|---|---|---|---|

## 无法核验事项
| 事项 | 缺少材料 | 不能判定的原因 |
|---|---|---|

## 本章评级
{A/B/C/D} — {一句理由}
(A=无 P0/P1;B=仅少量 P1;C=P1 较多或存在 P2;D=存在 P0)

【约束】
只读:不得修改用户任何文件,只允许写上述片段文件;不运行任何程序;
不补造文献、数据、结果;技能要求标"无法核验"的必须保留,不得判错。

【返回】
写完文件后仅返回:状态、问题计数(P0/P1/P2/P3)、评级、至多 3 条最重要的发现。
不要在返回中粘贴片段全文。
```

- 并行批次:第一波 01–04 同时派发;全部返回后再派第二波 05–07。串行时按 01→07 顺序。
- 每个 `{*_PATH}` 都必须是编排器已核实的绝对路径。

## 3. 内联执行(降级)

所在软件无子代理能力(Agent/Task/sub-agent 等),或同一检查器子代理连续两次失败时:

1. 主对话 Read 该技能 SKILL.md 与全部 references;
2. 按技能规则执行检查;
3. 按第 2 节同样的片段格式写盘;
4. 立即用 3–5 句把要点沉淀为文字结论再进入下一项,避免长文档细节滞留主上下文。

## 4. 汇总去重规则

- 同一问题被多个检查器命中:合并为一条,严重度取最高,保留全部证据位置,标注来源检查项。
- 交叉一致性问题(正文↔符号表、正文↔附录、声明↔AI 材料、摘要结论↔正文结果)单独归入总报告"四、交叉一致性问题"。
- 各章评级与 P0–P3 计数直接取自片段;总报告只浓缩引用,不得改写片段结论。
- 修改优先级路线 = P0 全部 → P1 → P2 → P3;同优先级内按"改动小、收益大"排序。

## 5. 异常处理

- 用户中途补料:补料后只重跑受影响的检查器,其余片段复用。
- 用户点名只查部分章节:只调度对应检查器,总报告其余行标"未在本次范围"。
- 子代理输出与技能原文规则冲突:以技能原文为准,并在该片段"状态"行注明偏差。
- 检查器中途被用户打断:已完成片段保留,总报告如实标注剩余项"未完成"。

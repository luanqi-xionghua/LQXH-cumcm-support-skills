# Paper Review — CUMCM 论文独立审查

## 定位与原则

- **CUMCM 优先**：默认按中国大学生数学建模竞赛（国赛）论文包和常见 `paper/outputs/results/submission/code` 结构发现材料；不依赖某一个具体编排流程，可用于不同年份、题型和自定义 CUMCM 工作流。
- **只读**：默认不修改论文、代码、数据或结果；审查只产出报告。
- **defect-first**：先列可操作问题，再给总体评价；没有证据的问题不编造。
- **分级**：`P0` 提交级阻塞（PDF 缺失、数字无法回溯、硬性提交结构缺失、关键结果无法复现）；`P1` 应修复（逻辑矛盾、过度声称、图表/匿名/AI 披露风险、核心方法缺少验证）；`P2` 建议改进（表达、排版、文献和非核心中间量）。
- **规则依赖**：页数上限、摘要/目录格式、匿名要求、AI 使用披露和提交结构必须以用户提供的当届官方章程或通知为准；未提供规则时标记“未核验”，不跨年份推断。机器预检中的 CUMCM 默认项是风险提示，不等同官方合规结论。
- **结论不冻结**：本技能输出人可读审查报告，不替代正式提交前审计、指导教师审核或官方评审。

## 触发方式

输入任一即可触发：

- `paper-review` / `paper review`
- `cumcm-review` / `cumcm review`
- `审查论文` / `评论文` / `review paper`

## 输入定位

1. 用户给出路径时，直接使用该论文 PDF、论文目录或提交包。
2. 未给路径时，在当前工作区按以下优先级发现：
   - 论文：`paper/`、`submission/论文/`、`outputs/`、`doc/`、`docs/`、根目录；取最新 PDF。
   - 结果：`results/`、`outputs/`、`output/`，重点寻找 `frozen_numbers.json`、`key_numbers.json`、`all_results.json`、`figure-manifest*`、运行清单。
   - 代码：`code/`、`src/`、`scripts/`、`submission/代码/`。
   - 数据：`data/`、`user_data/`、`datasets/`、`submission/数据/`。
3. 目录不符合默认约定时，优先通过脚本参数显式指定，不要因找不到约定产物而臆测论文有问题。

## 工作流

### Step 1：机器预检

运行：

```bash
python <技能目录>/scripts/review_paper.py --dir <论文包或工作区> [--pdf <主PDF>] \
  [--frozen <关键数值JSON>] [--json] [--no-consistency]
```

可按项目调整：

```bash
  [--internal-names 名1,名2] [--ai-log-name AI_USE_LOG.md] \
  [--no-ai-log-check] [--no-submission-check] \
  [--submit-dirs 论文,代码,数据,支撑材料]
```

预检覆盖：

- **论文结构**：页数；第 1 页摘要和关键词/关键字；第 2–4 页目录位置；关键词跨页提示；正文起止页的明显异常。
- **CUMCM 提交风险**：`submission/` 是否存在及论文、代码、数据、支撑材料目录；`AI_USE_LOG.md` 是否存在（仅作默认风险提示，可关闭；正式要求以当届规则为准）。
- **文本质量**：`??`、`TODO`、`【待复核】`、悬空 `ref`、内部工作流标识和强词（如“首次提出”“完美”“100%”）。默认内部标识包括 `RESULTS.md`、`frozen_numbers`、`all_results.json`、`key_numbers`、`run-manifest`、`MODELING_REPORT`、`PROBLEM_ANALYSIS`、`latex_includes`、`R2025B`、`RID-`、`cumcm-t2`、`workspace`。
- **图表和引用**：`figures/` 下 PDF 与 drawio/tikz 源的对应关系；LaTeX/Markdown 引用图片是否实际存在。
- **数字回溯**：`--frozen` 支持 `numbers` 列表和嵌套 dict；关键数值在 PDF 中按绝对/相对 0.1% 容差匹配；提取不到数值必须报 `FROZEN-SCHEMA`，不得静默通过。
- **三方一致性**：检测到代码或结果目录时自动运行 `consistency_check.py`，核对代码参数、冻结数值、结果 JSON、数据行数/数值范围与论文文本。

### Step 2：LLM 深审（9 个维度）

每个维度都给出“位置 + 证据 + 置信度（高/中/低）”：

1. **数字可回溯与可信**：摘要、核心表格和结论中的数字能否追溯到冻结数值、结果 JSON、运行记录或 RID；同时明确“可回溯不等于计算正确”。
2. **跨节逻辑一致性**：摘要↔正文、各问结论、假设↔模型使用、符号表↔公式、图表↔文字。
3. **CUMCM 合规性**：依据用户提供的当届规则核对摘要页数、正文页数、目录、匿名、附录/支撑材料、AI 使用披露、文件命名和提交结构；无规则项标“未核验”。
4. **排版质量**：图/表编号与题注格式、版面统一、overfull、裁切、箭头缺失、乱码、公式和参考文献异常。
5. **反 AI 与可信表达**：元叙述泄露、模板指纹、过度声称、异常完美数值、长表格；对最优时点、AUC、敏感度等关键结论检查是否只有点估计而无区间、对照或稳健性说明。
6. **图表完整性**：总流程图、各小问流程图/机理图是否足够支撑 CUMCM 评审阅读；每图每表是否在正文引用。
7. **文献与对照**：引用是否真实支撑相邻陈述；是否说明同题/同类方法、基线、参数区间和差异；不得虚构文献。
8. **可复现性**：代码、数据、结果和论文数字一致；seed、环境、依赖、运行清单、输入输出和异常预案是否完整。
9. **方法学健全性**：多重共线性（如派生变量/BMI）、删失/缺失不可识别性、阈值或超参数泄漏、个体分组交叉验证、小样本置信区间、简单够用模型、敏感性分析及验证检查点。

若存在 `MODELING_REPORT.md` 或同类方法学/模型冻结文档，额外对照其“结果约束、预期行为、异常预案、方法唯一性、验证检查点”五项声明；没有则标未发现，不报错。

### Step 3：输出

1. 写入 `checks/paper-review.md`，使用 `assets/review-report-template.md`：审查对象 PDF 路径、SHA-256、页数；可选审查基线；P0/P1/P2 清单；9 维度结论；优点与风险；机器预检附件。
2. 对话中先给 Top 5 问题（严重度、一句话、是否值得修），再询问是否需要按 P1 修复；不自动改稿。
3. P0/P1 修复建议必须指出受影响的上游产物（冻结数值、模型、代码、数据、运行标识等）和建议重跑命令；不能只建议“修改文字”。

## CUMCM 适配与参数

- 当届规则文件/链接/粘贴文本优先于本技能的默认提示。
- `--internal-names` 可加入题号、项目代号、内部路径和工作流专属标识。
- `--submit-dirs` 可改成具体提交包目录；如果不采用提交包检查，使用 `--no-submission-check`。
- 如果赛事或学校不要求 AI 记录，使用 `--no-ai-log-check`；如果要求且文件名不同，使用 `--ai-log-name`。
- `consistency_check.py` 内置 seed、random_state、CUMCM 常见参数（波段、折射率、阈值、入射角、噪声比例等）与全大写常量提取，也支持多次 `--param-pattern "正则=标签"`。

## 与其他 CUMCM 工作流协作

- 可在任意建模流程结束后运行，不要求 `cumcm-t2`。
- 若流程存在 stage/agent 交接记录，将其作为可复现性证据；不存在则只检查实际存在的材料。
- 可将新发现的问题类型回灌到团队自己的检查清单，但本技能默认不修改工作流规范。

## 边界

- 默认只读；用户明确要求修复时，先列修改计划，再逐项实施。
- 不执行外部 `.exe`、`.lnk`、未知二进制或 Office 宏。
- 不引用其他年份、其他赛事或未经用户提供的规则判断 CUMCM 合规。
- 长论文采用“脚本预检 + 分节深审”，报告只保留有证据且可行动的问题。
